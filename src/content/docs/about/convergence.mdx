Open three chat tabs — Claude, GPT, Gemini — and give each the same bare prompt:
*"build me a todo app,"* nothing else. Then diff the three `package.json` files.
They rhyme. Run the same test across more than forty families — raw models, app
builders, and coding agents — and the <a href={withBase('explorer/')}>explorer's matrix</a> makes
the shape obvious at a glance.

## The shape of the agreement

The columns don't all converge equally, and that's the interesting part (counted
over the families that name a concrete default — the ones that "mirror the project"
are set aside):

- **State & data is a single answer.** Every family that commits to a default
  reaches for TanStack Query. Not _almost_ every — every one.
- **Styling is all but a settled answer.** Nearly every family that names a styling
  default picks Tailwind. The only holdouts are NativeWind (just Tailwind's React
  Native cousin) and Plasmic, the rare tool that defaults to plain CSS.
- **Components mostly converge.** Where a tool commits to a component library it's
  shadcn/ui; the rest decline to pick one rather than choosing a rival.
- **The framework wobbles.** Next.js leads, Vite holds a real minority, and the
  mobile builders branch off to React Native + Expo.
- **The backend scatters.** Here defaults genuinely diverge — Supabase leads but
  only as a plurality, with Firebase, Vercel, AWS, and proprietary backends
  splitting the rest.

So the monoculture isn't total. It's concentrated in the layers closest to the
code the model writes character by character, and it loosens as you move toward
infrastructure.

There's a second axis the broader dataset exposes: **builders impose, agents
inherit.** App builders (v0, Lovable, Firebase Studio, …) bake the consensus stack
into their templates. Coding agents (Cursor, Windsurf, Devin, …) mostly mirror your
existing project instead — so they don't _add_ a vote for the monoculture, but they
inherit it from the model driving them, and from the training data underneath that.

## Why it happens

<CardGrid>
	<Card title="Token economics" icon="rocket">
		Tailwind's atomic utility classes are cheap to emit — short, predictable
		tokens inline in the markup — where CSS-in-JS or separate stylesheets cost
		more tokens and more round-trips. The cheapest correct answer wins by default.
	</Card>
	<Card title="Open code, not an API" icon="seti:react">
		shadcn/ui ships components as source you copy in, not an opaque package with
		an API to memorize. That maps perfectly onto how a model generates — it would
		rather write the component than import one it has to recall the surface of.
	</Card>
	<Card title="The training flywheel" icon="approve-check">
		Popular code becomes training data becomes the next model's default becomes
		more popular code. Each turn of the wheel tightens the consensus, regardless
		of whether the alternatives got worse.
	</Card>
</CardGrid>

## The cost

The flywheel has two side effects worth naming:

1. **Permanent version lag.** Models default to the library versions that dominated
   their training data, not the latest release. The default is always slightly
   behind — and the lag is structural, not a bug that gets fixed.
2. **Alternatives fall out of view.** Frameworks outside the consensus don't lose on
   quality; they lose on *visibility*. If the model never reaches for them, most
   people scaffolding with a model never see them.

None of this means the default stack is wrong — it's a genuinely good stack. The
point is that "good" and "the only thing you're shown" are different properties,
and the gap between them is widening.
